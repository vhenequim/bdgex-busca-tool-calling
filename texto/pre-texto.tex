\begin{resumo}
\SingleSpacing
O acervo cartográfico da Diretoria de Serviço Geográfico (DSG), disponível no Banco de Dados Geográficos do Exército (BDGEx), é organizado por nomenclaturas técnicas, como o Índice de Nomenclatura e o Mapa Índice, que tendem a restringir o seu uso por não especialistas. Para disseminar a informação geoespacial, deseja-se a busca em linguagem natural, traduzida por um modelo de linguagem nos critérios do catálogo. O projeto \texttt{prototipo\_busca\_llm}, desenvolvido pelo Maj Diniz no 1º Centro de Geoinformação (1º CGEO), fazia essa tradução com saída estruturada, em que o modelo preenche um formato fixo, com um só modelo local (Phi-4 14B) e um dicionário de normalização, sem protocolo de avaliação. O objetivo deste trabalho foi adequar esse projeto ao \textit{tool calling}, em que o modelo escolhe se chama ferramentas e com quais argumentos. A primeira das três versões desenvolvidas oferece só a ferramenta de busca, numa única chamada ao modelo. A segunda acrescenta uma ferramenta de recusa e escreve nas descrições das ferramentas convenções do manual que define o gabarito. A versão final acrescenta ferramentas auxiliares do domínio, como a identificação de nomes e a resolução de períodos, que o modelo consulta em sucessivas chamadas, e uma verificação dos parâmetros que lhe devolve os erros. Foram construídos três conjuntos de consultas, de referência (\res{principal}{geral}{ntotal}, com gabarito auditado), de validação (\res{lotedados}{geral}{aceitas}) e de teste (\res{lote2dados}{geral}{aceitas}, nunca usado no desenvolvimento). Foi desenvolvido um \textit{pipeline} reprodutível para avaliar as versões em quatro modelos locais, executados pelo Ollama, e compará-las com a solução do Maj Diniz e com a saída estruturada (teste A/B, também com três modelos maiores em nuvem). Na primeira versão, com os três melhores modelos locais, o \textit{tool calling} não diferiu significativamente em acurácia da solução do Maj Diniz (\res{abordagens}{prototipo}{acuracia} no conjunto de referência) e teve tempo de resposta uma ordem de grandeza menor, pela troca por modelos menores. No conjunto de teste, a versão final com o Gemma 4 E4B obteve acurácia de \res{lote2}{tc3}{acuracia}, contra \res{lote2}{se3}{acuracia} do controle, a saída estruturada com as mesmas descrições e a mesma verificação, sem as ferramentas auxiliares e outras peças do \textit{tool calling}. Essa vantagem repetiu-se com o Gemma 4 E2B e inverteu-se com o Qwen 3 4B. No teste A/B, em pares com o mesmo modelo, conjunto e versão, a abordagem mais acurada dependeu da versão e do modelo, e o \textit{tool calling}, sem ganho de tempo, obteve o maior F1 da recusa em todos os pares fora do desenvolvimento. Numa análise complementar no acervo real, as buscas registradas da versão final com o Gemma 4 E4B devolveram as mesmas cartas que o gabarito em \res{acervo}{tc3}{accresultcartas} das consultas de teste com cartas no gabarito. Ressalva-se que as consultas são sintéticas e que as ferramentas e a verificação codificam o mesmo manual que define o gabarito.

\textbf{Palavras-chave:} Modelos amplos de linguagem. \textit{Tool calling}. Catálogo de dados espaciais. Disseminação da informação geoespacial. Cartografia sistemática. Ollama. Avaliação de modelos.

\end{resumo}

% resumo em inglês
\begin{resumo}[Abstract]
 \begin{otherlanguage*}{english}
\SingleSpacing
The cartographic collection of the Brazilian Army Geographic Service Directorate (DSG), in the Army Geographic Database (BDGEx), is organized by technical nomenclatures, such as the Nomenclature Index and the Index Map, that tend to restrict its use by non-specialists. To disseminate geospatial information, natural-language search is desirable, with a language model translating the free-form query into the criteria of the catalog. The \texttt{prototipo\_busca\_llm} project, developed by Maj Diniz at the 1st Geoinformation Center (1º CGEO), performed this translation with structured output, in which the model fills a fixed format, using a single local model (Phi-4 14B) and a normalization dictionary, without an evaluation protocol. The objective of this work was to adapt that project to tool calling, in which the model chooses whether to call tools and with which arguments. The first of the three versions developed offers only the search tool, in a single model call. The second adds a refusal tool and writes into the tool descriptions conventions of the manual that defines the ground truth. The final version adds auxiliary domain tools, such as name identification and period resolution, which the model consults over successive calls, and a parameter check that returns the errors to it. Three query sets were built, the reference set (\resen{principal}{geral}{ntotal}, with an audited ground truth), the validation set (\resen{lotedados}{geral}{aceitas}), and the test set (\resen{lote2dados}{geral}{aceitas}, never used in development). A reproducible pipeline was developed to evaluate the versions on four local Ollama models and to compare them with Maj Diniz's solution and with structured output (A/B test, also with three larger cloud models). In the first version, with the three best local models, tool calling did not differ significantly in accuracy from Maj Diniz's solution (\resen{abordagens}{prototipo}{acuracia} on the reference set) and had a response time one order of magnitude shorter, owing to the change to smaller models. On the test set, the final version with Gemma 4 E4B reached an accuracy of \resen{lote2}{tc3}{acuracia}, against \resen{lote2}{se3}{acuracia} for the control, structured output with the same descriptions and the same parameter check, without the auxiliary tools and other parts of tool calling. This advantage recurred with Gemma 4 E2B and reversed with Qwen 3 4B. In the A/B test, in pairs with the same model, query set and version, the more accurate approach depended on the version and the model, and tool calling, with no gain in time, had the higher refusal F1 in every pair outside development. In a complementary analysis on the real collection, the recorded searches of the final version with Gemma 4 E4B returned the same maps as the ground truth in \resen{acervo}{tc3}{accresultcartas} of the test queries with maps in the ground truth. As caveats, the queries are synthetic, and the tools and the parameter check encode the same manual that defines the ground truth.

   \noindent
   \textbf{Keywords:} Large language models. Tool calling. Spatial data catalog. Geospatial information dissemination. Systematic topographic mapping. Ollama. Model evaluation.
 \end{otherlanguage*}
\end{resumo}
